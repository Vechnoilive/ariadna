# Руководство оператора программного комплекса Ариадна

Внутреннее обозначение АРИАДНА.09.01.34. Версия программы 0.9.0. Редакция документа от 13.11.2026. Разработчик: Заречкин Артём Алексеевич, группа Б24-507.

## Аннотация

Документ описывает локальный запуск, работу с домашними и полевыми миссиями, получение журналов и действия при ошибках. Для просмотра сохранённых записей достаточно браузера; новый расчёт требует Python-сервера.

## 1 Назначение программы

Комплекс моделирует взаимодействие неоднородных агентов, позволяет сравнивать контроллеры и проверять причины изменения совместного плана. Он предназначен для модельных испытаний и демонстрации. Контроллер не управляет реальными устройствами.

## 2 Условия выполнения

Требуется Python 3.11 или новее с совместимой стандартной библиотекой. В проекте заявлена матрица 3.11–3.13; текущая проверка выполнена только на платформе, указанной в TEST_PROTOCOL.md. pip install для прямого запуска не нужен. GPU, Docker и ключи API не требуются.

Интерфейс использует браузер с JavaScript и WebGL 2; предусмотрен резервный SVG-рендер. Three.js включён локально. Node.js необходим только для пересборки движка и браузерных проверок. Для редактируемых документов дополнительно нужны python-docx, а для PDF — LibreOffice. Эти средства не являются зависимостями миссии.

Рабочая рекомендация — 2 ядра, 2 ГиБ свободной памяти и не менее 500 МиБ диска для проекта и части журналов. Это не измеренная нижняя граница: большие серии создают значительно больше данных. Порты 8080, 8000 и 8001 должны быть свободны при использовании значений по умолчанию.

## 3 Запуск и завершение

Распакуйте проект и откройте терминал в каталоге с README.md. В Windows запустите start.bat. В Linux или macOS выполните:

```bash
python3 scripts/start_local.py --open
```

Команда открывает «Квартиру 42» по http://127.0.0.1:8080/home.html. Полевые миссии доступны по кнопке в интерфейсе или адресу http://127.0.0.1:8080/index.html. Ключ --field открывает полевую страницу сразу. Если порт занят, укажите --port 8081.

Для остановки нажмите Ctrl+C в терминале и дождитесь завершения сервера. Повторный запуск создаёт новый процесс; незавершённый эпизод не восстанавливается автоматически. Сохранённую запись можно посмотреть без расчёта, открыв viewer/home.html либо viewer/index.html в браузере.

## 4 Работа с интерфейсом

В квартире выберите один из трёх случаев, запустите воспроизведение и проследите события на шкале. «Вход залит» показывает обход курьера; «Связь вернулась» — перемещение ретранслятора; закрытие кабинета — оба заблокированных прохода и остановку. Карта вращается мышью; выбор робота показывает его состояние и габариты. Обучение доступно через «Как пользоваться».

Раздел «Решения» связывает команды, роли и объяснения с модельным временем. «Развилка» сравнивает планы из общего снимка собственной среды. Прогнозы следует отличать от измеренных траекторий. Слой габаритов отображает корпуса и защитный зазор, а сеть — доступность каналов.

На полевой странице доступны пять исходных операций и дополнительный «Орбитальный мост». В редакторе можно загрузить пресет или подготовить собственную карту, затем нажать «Запустить на этой карте». Пока миссия выполняется, редактирование заблокировано. Карта фиксируется до начала расчёта; просмотр прошлой записи не пересчитывает её физику.

## 5 Раздельный запуск и получение журналов

Для проверки HTTP откройте два терминала в корне проекта. В первом запустите среду, во втором — переносимый контроллер. Каталог журналов создаётся при записи.

```bash
python3 -m hackroi environment --port 8000 --log-path artifacts/manual/environment.jsonl
```

```bash
python3 -m hackroi controller --portable --port 8001 --environment-url http://127.0.0.1:8000 --seed 42 --run-id manual_001 --log-path artifacts/manual/controller.jsonl
```

Оба процесса печатают событие ready. Контроллер после эпизода печатает episode_complete и продолжает обслуживать health до Ctrl+C. Ключи --portable, --meta, --counterfactual и --baseline fixed или reactive взаимоисключающие. Чтобы повторить опыт, используйте новые процессы и каталог.

Проверка пары журналов:

```bash
python3 -m hackroi audit --environment-log artifacts/manual/environment.jsonl --controller-log artifacts/manual/controller.jsonl
```

Аудит проверяет связь записей и воспроизводимость решения. Passed не означает официального допуска организаторами. Для чужой среды используйте scripts/run_external.py --url http://HOST:PORT только с согласованным адресом; команда начинает новый эпизод.

## 6 Воспроизводимые серии и документы

Серия квартиры с тремя алгоритмами и отдельным пакетом просмотра:

```bash
python3 scripts/run_home.py --output artifacts/home_new --publish artifacts/home_new_replay.js
```

Текущие полевые расстановки с двумя контрольными алгоритмами:

```bash
python3 scripts/run_missions.py --dispersed --baselines --output artifacts/field_new
```

Каталоги должны быть новыми. Полевой скрипт возвращает ненулевой код при ошибке или непрошедшем аудите; частичные результаты при этом сохраняются. Сначала прочитайте summary.json и журналы, затем решайте, нужен ли повтор.

Основная проверка кода и поставки:

```bash
python3 -m unittest discover -s tests -v
python3 scripts/check_schemas.py
python3 scripts/check_scenarios.py
python3 scripts/check_delivery.py
python3 scripts/check_documents.py
python3 scripts/check_cosmic.py
```

Печатные файлы пересобираются командой python3 scripts/build_documents.py --output artifacts/documents_new --pdf. Для сборки нужны python-docx, pypdf и LibreOffice; при необходимости путь к soffice задаётся ключом --soffice. Сборщик экспортирует PDF, сверяет страницы и повторяет вёрстку до согласования содержания. Для обновления submission используется --force --pdf. После сборки проверяются изображения всех страниц. Презентация находится в submission/defense.pptx; её обновление из исходного шаблона выполняет scripts/build_presentation.mjs.

## 7 Сообщения оператору

Таблица 1 - Ошибки и действия оператора

| Сообщение или код | Значение | Действие |
|---|---|---|
| Address already in use | Порт занят | Завершить прежний процесс или выбрать другой --port |
| UNKNOWN_EPISODE | Эпизод отсутствует или другой | Запустить новый reset в согласованном процессе |
| INVALID_REQUEST | Неверная схема или повтор идентификатора с иным телом | Проверить запрос; для повтора сохранить прежнее тело |
| INVALID_COMMAND | Действие недоступно | Сверить available_actions и параметры |
| CONSTRAINT_VIOLATION | Нарушены ресурсы, путь или ограничения | Прочитать details и исправить план |
| RESOURCE_EXHAUSTED | Исчерпан ресурс или лимит запросов | Сверить details; при лимите кэша начать новый процесс |
| TIMEOUT или потеря ответа | Результат запроса неизвестен | Сохранить журналы; автоматически не повторять POST с новым id |
| safe_stopped | Исполнена безопасная остановка | Проверить директиву и причину; это не success доставки |
| time_limit | Достигнут лимит времени | Оценить полноту и последнюю причину решения |

После неожиданного завершения не изменяйте исходные журналы. Сохраните команду, карту, seed и версию. При доступном живом процессе повтор изменяющего запроса возможен только с тем же request_id и телом; после перезапуска старое состояние кэша утрачено.

## 8 Космический ретранслятор и схемы ветвей

В полевых сценариях выберите «Орбитальный мост». Запустите готовую запись либо кнопку нового расчёта. Блок «Орбита 01» показывает реальные каналы, число агентов, маршруты которых проходят через спутник, исполненные команды relay и энергию. Кнопка перехода к 4-й секунде открывает момент отказа наземных ретрансляторов. На 9-й секунде поступает SOS. Спутник виден в трёхмерной сцене, в списке агентов, решениях и журнале. Сеть включается переключателем слоя связи.

В «Развилке» показаны две двумерные схемы в одинаковом масштабе. Двигайте общую шкалу и выбирайте альтернативу справа. Зелёные узлы находятся на связи, оранжевые отключены, красные обозначают отказ; спутник выделен фиолетовым. Линии показывают фактические каналы, пунктир — спутниковые звенья. Подсказка узла содержит имя и высоту.

В сохранённой паре со спутником получены 100 % и успех за 19 с; без спутника — 0 % и безопасная остановка на 31 с. Это один модельный случай, оба журнала прошли аудит.

Парные измерения со спутником и без него воспроизводятся командой python3 scripts/build_cosmic.py. Она запускает независимые HTTP-процессы, проверяет журналы и обновляет космическую демонстрацию. Новые результаты следует сравнивать с cosmic_summary.json, сохраняя seed и параметры карты.
